# QA Helper

## О проекте

**QA Helper** — это веб-платформа для автоматизации процессов тестирования, которая объединяет:

- **AI-ассистента** для генерации тест-кейсов и анализа требований;
- **Статический анализ** тест-кейсов из ТестОпс;
- **Test Impact Analysis (TIA)**: маппинг изменений кода на тестовую модель;
- **Тестирование требований** при помощи AI;
- **Интеграцию с Jira** для работы с дефектами;
- **Конвертацию XMind** в структуру ТестОпс

Проект состоит из трёх основных компонентов:
1. **Фронтенд** (React SPA);
2. **Бэкенд** (Node.js);
3. **TIA Mapping Service** (Node.js + PostgreSQL) — сервис маппинга компонентов

## Возможности

### Статический анализ тест-кейсов

**Предварительные условия для выполнения анализа:**

Тест-кейсы должны быть привязаны к задаче "Тестовая документация" через связанные задачи из баг-трекера

**Основные функции:**
- Проверка обязательных полей (статус, приоритет, версия);
- Валидация структуры шагов (синтаксис, полнота описания);
- Проверка наличия тегов окружения и слоев;
- Анализ ожидаемых результатов и предусловий;
- Генерация HTML-отчётов о проверке

**Правила валидации:**
- Статус тест-кейса должен быть "Review";
- Заполнены кастомные поля "Priority" и "Version";
- Указан хотя бы один тег окружения (M, D, A, S, PWA);
- Шаги начинаются с глагола в неопределённой форме;
- Присутствует хотя бы один шаг;
- Заполнен общий ожидаемый результат;
- Указан слой (E2E Tests / Integration frontend Tests / Integration backend Tests)

#### Как предлагать новые правила для статического анализа?
Завести идею Head of QA

### Test Impact Analysis (TIA)

**Основные функции:**
- Загрузка JSON-файлов с компонентами;
- Автоматическое получение структуры функциональных блоков из ТестОпса;
- Создание маппинга между компонентами кода и функциональными блоками;
- Сохранение маппингов в базе данных для повторного использования;
- Автоматическое формирование тест-планов на основе изменённых компонентов;

### AI-генерация тест-кейсов на основе требований

**Источники требований:**
- Текстовое описание;
- Страницы Confluence (по Page ID);
- Файлы документации;
- Дополнительный контекст: глоссарий проекта или описание системы

**Процесс генерации:**
1. **Анализ требований** — AI изучает требования и контекст;
2. **Генерация тестовой модели** — создаётся иерархия Feature > Story > Scenario > Code;
3. **Ревью и корректировка** — получившуюся модель можно отредактировать вручную;
4. **Генерация тест-кейсов** — на основе модели создаются тест-кейсы;
5. **Создание в ТестОпс/Jira** — автоматическая отправка через API

### Экспорт XMind в ТестОпс

Конвертация тестовой модели из XMind в структуру ТестОпса

**Основные функции:**
- Парсинг .xmind файлов
- Создание папок и тест-кейсов в выбранном проекте ТестОпса через API

### Работа с дефектами и Jira

**Функции для дефектов:**
- Получение дефектов из ТестОпса;
- Создание задач в Jira из дефектов;
- AI-заполнение полей задачи на основе описания дефекта;

**Заведение набора ошибок кода на эпик:**
- Массовое создание задач в Jira;
- Автоматическая привязка к эпику;
- Заполнение полей задачи на основе типа ошибки

## Быстрый старт

### Docker Compose
```bash
# Клонировать репозиторий
git clone ssh://git@git.abanking.ru:2244/vpoliakov/allure-test-inspector.git
cd allure-test-inspector

# Запустить контейнеры
docker-compose up -d

# Проверить статус
docker-compose ps
```

Приложение будет доступно на:
- Фронтенд: http://localhost:3000
- Бэкенд: http://localhost:5000
- TIA Mapping Service: http://localhost:5001

Для остановки:
```bash
docker-compose down
```

## Сборка и установка
### Настройка PostgreSQL

```bash
# Подключиться к PostgreSQL
sudo -u postgres psql

# Создать базу данных
CREATE DATABASE tia_db;

# Создать пользователя (опционально)
CREATE USER tia_user WITH ENCRYPTED PASSWORD 'your_password';
GRANT ALL PRIVILEGES ON DATABASE tia_db TO tia_user;

# Выход
\q
```

### Установка зависимостей

#### 1. Клонирование репозитория

```bash
git clone ssh://git@git.abanking.ru:2244/vpoliakov/allure-test-inspector.git
cd allure-test-inspector
```

#### 2. Установка зависимостей бэкенда

```bash
# В корне проекта
npm i --legacy-peer-deps
```

#### 3. Установка зависимостей фронтенда

```bash
cd client
npm i --legacy-peer-deps
cd ..
```

#### 4. Установка зависимостей TIA Mapping Service

```bash
cd tia-mapping-service
npm install
```

### Применение миграции базы данных

```bash
cd tia-mapping-service

# Выполнить миграции
npm run migrate

# Или через Knex CLI, если установлен глобально
npx knex migrate:latest

cd ..
```

Миграции создадут необходимые таблицы в базе данных:
- `component_mappings` — хранение маппингов компонентов на функциональные блоки
- `functional_blocks ` — кэш структуры из ТестОпса
- `test_plans` — история созданных тест-планов
- `errors_log`

### Конфигурация для локальной сборки
Для работы в локальном окружении необходимо изменить:
- в `server/config.json` — значение параметра "url" на "http://localhost:5000"
- в `client/config.json` — параметра "serverUrl" на "http://localhost:5000/api"

### Запуск приложения

**Терминал 1 — Сервер бэкенда:**
```bash
npm run run
# или
node server/server.js
```

**Терминал 2 — TIA Mapping Service:**
```bash
cd tia-mapping-service
npm start
# или
node server.js
```

**Терминал 3 — Фронтенд:**
```bash
cd client
npm start
```

Frontend откроется автоматически на http://localhost:3000  
Main Server API: http://localhost:5000  
TIA Service API: http://localhost:5001

Логи серверов доступны в соответствующих терминалах IDE
