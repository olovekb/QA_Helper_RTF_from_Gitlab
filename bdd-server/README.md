# BDD Test Generator Server

Сервер для генерации BDD тестов (Gherkin) с дедупликацией шагов через векторную базу данных.

## Возможности

- ✅ Генерация Gherkin `.feature` файлов из требований
- ✅ Дедупликация шагов через векторную БД (Pinecone)
- ✅ Асинхронная генерация с отслеживанием прогресса
- ✅ Переиспользование существующих шагов из базы
- ✅ Трёхэтапная архитектура: Парсинг → Нормализация → Генерация

## Архитектура генерации

BDD генератор работает по трёхэтапному конвейеру:

### Шаг 1: Парсинг ЧТЗ (10-30%)
- Разбивает документ по подтребованиям (3.1.1, 3.1.2, 3.2.1 и т.д.)
- Приводит каждый фрагмент к структурированному JSON:
  ```json
  {
    "id": "3.1.1",
    "element": "Название элемента",
    "requirement": "Описание требования",
    "methods": ["GET /api/..."],
    "parameters": [{"name": "param", "type": "string"}],
    "type": "UI-отображение|навигация|валидация|..."
  }
  ```
- Маркирует тип: UI-отображение, навигация, валидация поля, обработка ошибки, вызов сервиса, изменение данных

### Шаг 2: Нормализация в "правила" (30-60%)
- Извлекает независимые правила поведения для каждого фрагмента
- Каждое правило содержит:
  - `requirementId` - ID требования
  - `rule` - описание правила
  - `precondition` - предусловие
  - `expectedResult` - ожидаемый результат
  - `type` - тип правила

### Шаг 3: Генерация BDD (60-90%)
- Для каждого правила создаёт 1-3 Gherkin сценария
- Использует векторную БД для дедупликации шагов
- Применяет канонические формулировки из базы
- Использует Scenario Outline + Examples для параметризации
- Группирует сценарии по Feature

## Установка

```bash
cd bdd-server
npm install
```

## Настройка

### Быстрый старт

Для тестирования можно запустить без дополнительной настройки:
```bash
npm install
npm start
```

Сервер будет работать в режиме in-memory (данные не сохраняются после перезапуска).

### Полная конфигурация

Кратко: создайте файл `.env` в корне проекта:

```env
# База данных для задач генерации (та же что и основной сервер)
DATABASE_URL=postgresql://user:password@localhost:5432/dbname

# Pinecone для векторной БД (опционально)
PINECONE_API_KEY=your-pinecone-api-key
PINECONE_INDEX_NAME=gherkin-steps

# OpenAI для эмбеддингов (если используется Pinecone)
# Cloud.ru не предоставляет embeddings API, поэтому используем OpenAI
OPENAI_API_KEY=your-openai-api-key

# Порт сервера
BDD_SERVER_PORT=5002
```

**Примечание**: Все компоненты опциональны. Сервер будет работать даже без БД и Pinecone, но с ограниченной функциональностью.

## Запуск

```bash
npm start
```

Сервер запустится на `http://localhost:5002`

## API Эндпоинты

### POST `/api/bdd/generate`

Запускает генерацию BDD тестов.

**Request:**
```json
{
  "requirements": "Текст требований...",
  "modelStructure": [...],
  "projectId": "199"
}
```

**Response:**
```json
{
  "taskId": "uuid",
  "status": "started"
}
```

### GET `/api/bdd/status/:taskId`

Проверяет статус генерации.

**Response:**
```json
{
  "id": "uuid",
  "status": "completed",
  "progress": 100,
  "result": {
    "feature": "Feature: ...",
    "steps": [...]
  }
}
```

### GET `/api/bdd/steps`

Получает список всех сохранённых шагов (для отладки).

## Архитектура

1. **Векторная БД (Pinecone)**: Хранит уникальные шаги Gherkin с векторными эмбеддингами
2. **Локальное хранилище**: Fallback если Pinecone недоступен
3. **Дедупликация**: Перед генерацией ищет похожие шаги и предлагает их переиспользовать
4. **Асинхронная генерация**: Использует ту же БД задач что и основной сервер

## Интеграция с Allure TestOps

BDD тесты можно экспортировать в `.feature` файлы и импортировать в Allure TestOps через:
- Git репозиторий (CI/CD пайплайн)
- Прямой импорт через API (будет реализовано)
