# Интерфейс TIA

Данный модуль представляет собой рабочее пространство для анализа влияния изменений в коде на функциональность системы и автоматизированного создания запусков тестирования в Allure.

## Основное назначение

Интерфейс TIA позволяет решать следующие задачи:
1. Визуализация изменений в коде на основе загруженных JSON-отчетов.
2. Маппинг между программными компонентами и функциональными блоками в Allure.
3. Оценка рисков изменений на основе AI-анализа и исторической критичности кода.
4. Создание запусков в Allure, включающих только те тесты, которые затрагивают измененный код.

## Архитектура модуля

Разделен на следующие логические части:

*   **context/**: Содержит `TIAContext.jsx`, который является "единым источником истины". В нем сосредоточены:
    1. Состояние загруженных отчетов и текущих маппингов.
    2. Логика взаимодействия с API сервиса маппинга.
    3. Функции управления модальными окнами и процессами создания запусков.
*   **views/**: Содержит основные компоновочные блоки страницы, такие как `TIASplitWorkspace.jsx`. Этот компонент обеспечивает разделение экрана на список компонентов и дерево функциональных блоков.
*   **ui/**: Набор переиспользуемых визуальных элементов. Ключевой компонент — `TIAComponentCard.jsx`, который отвечает за отображение деталей изменения, уровня риска и текущих связей компонента.
*   **modals/**: Специализированные окна для сложных операций, включая `TIAMappingModal.jsx` (интерфейс связывания) и `TIASplitModal.jsx` (распределение блоков по отдельным запускам).
*   **utils/**: Содержит `tiaUtils.js` — библиотеку функций для обработки данных. Здесь реализованы алгоритмы поиска по дереву, парсинг сложных форматов JSON и правила наследования маппингов.

## Механика работы маппинга

Процесс установления связей строится на иерархическом подходе:

1. Прямой маппинг: Пользователь вручную связывает компонент кода с конкретным блоком в Allure. Это сохраняется в базе данных и имеет наивысший приоритет.
2. Наследование: Если компонент не связан напрямую, система анализирует его зависимости. Через TIA-отчет выявляются страницы, которые зависят от этого кода. Если у этих страниц уже есть настроенный маппинг, он предлагается как "наследуемый" (отображается желтым цветом).
3. Идентификация бэкенда: Бэкенд-компоненты всегда идентифицируются по паре `путь_к_файлу::имя_метода`. Это исключает ошибки при наличии методов с одинаковыми именами в разных сервисах.

## Взаимодействие с внешними сервисами

Для работы модуля необходим запущенный `tia-mapping-service`, который предоставляет следующие эндпоинты:

1. `/api/structure`: Предоставляет дерево функциональных блоков Allure для текущего проекта.
2. `/api/components`: Обработка сохранения и получения связей между кодом и блоками.
3. `/api/launch`: Команда на формирование и постановку в очередь запуска в Allure.
4. `/api/components/page-mappings`: Получение данных о связях страниц для реализации механизма наследования.

## Рекомендации для разработчиков

При внесении изменений в модуль следует придерживаться следующих правил:
*   Любое новое глобальное состояние должно добавляться в `TIAContext.jsx` и очищаться в функции `resetStates`.
*   Все тяжелые операции по обработке данных (фильтрация, поиск по дереву) следует выносить в `tiaUtils.js`.
*   Для получения доступа к данным внутри компонентов необходимо использовать хук `useTIA()`.
*   При добавлении новых асинхронных функций в контекст важно соблюдать корректный порядок их определения для исключения ошибок инициализации зависимостей в `useCallback`.
