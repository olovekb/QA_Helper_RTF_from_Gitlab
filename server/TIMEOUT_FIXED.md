## 🎯 ПОЧЕМУ ГЕНЕРАЦИЯ МЕДЛЕННАЯ?

### **Причины:**

1. **Накопление контекста LLM** 🧠
   - Контекст растёт с каждым chunk
   - Больше контекст = медленнее генерация

2. **Большой max_tokens** 📝
   - max_tokens = 45000 для полного ответа
   - LLM генерирует много токенов

3. **Последовательная генерация** 🔄
   - Chunk за chunk (не параллельно)

4. **Сброс контекста работает** ✅
   - Каждые 3 chunks контекст сбрасывается
   - Но всё равно может быть медленно

## 🚀 ЕСЛИ ВСЁ ЕЩЁ ДОЛГО:

### **Вариант 1: Уменьшить max_tokens (для отладки)**

В `server/server.js` найти:
```javascript
max_tokens: 45000
```

Заменить на:
```javascript
max_tokens: 15000  // Только для отладки! Не для продакшена!
```

⚠️ **ВНИМАНИЕ:** Это может привести к неполной генерации, но ускорит процесс.

---

### **Вариант 2: Увеличить частоту сброса контекста**

В `server/server.js` найти:
```javascript
if (i > 0 && i % 3 === 0) {  // Каждые 3 chunks
    currentContextId = `${taskId}-reset-${Math.floor(i / 3)}`;
    console.log(`[CONTEXT RESET] Chunk ${i}: сброс контекста → ${currentContextId}`);
}
```

Заменить `3` на `1`:
```javascript
if (i > 0 && i % 1 === 0) {  // Каждый chunk
    currentContextId = `${taskId}-reset-${i}`;
    console.log(`[CONTEXT RESET] Chunk ${i}: сброс контекста → ${currentContextId}`);
}
```

⚠️ **ВНИМАНИЕ:** Это может снизить качество, но ускорит генерацию.

---

### **Вариант 3: Использовать более быструю модель**

В `server/config.json`:
